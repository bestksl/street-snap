# 行色 / Xingse

预览和 JPEG 共用 `ColorRecipe` 与 GLSL 调色实现。输入为 SDR 图像；照片在解码、方向校正后以 sRGB 送入 GPU。手机 ISP 会影响最终观感，预览和 JPEG 的曝光、降噪等处理也可能不同。

## 内置影调

- **正片**：较深的阴影、鲜明的颜色、微暖高光，借鉴便携相机正片模式的表现方向。
- **负片**：抬起黑位、收敛高光、暖色主体和微冷阴影；这里指负片冲印后的影调，不是反相。
- **粉末蓝**：提升中间调，选择性柔化蓝色、略向清新青蓝靠拢；保留黑白端点、中性色和暖色主体的色度，不全局去饱和或覆盖蓝色蒙版。
- 原色、黑白、晴街和用户导入的 `.cube` 继续保留。

上述色表由 `BuiltInLuts.kt` 的公开公式生成，独立调校，没有使用原厂固件或提取色表。它们不代表理光 GR、适马或其他相机的原厂输出，也不存在品牌授权关系。

粉末蓝的参考方向来自 [SIGMA 官方 Color Mode Library](https://www.sigma-global.com/en/shooting-with-sigma/sigma_color_mode_library/#Powder%20Blue)：原文是 “a bright, transparent look with a fresh blue color”，并说明相对 Standard 提升中间调。这里据此设计原创配方；选择性蓝色柔化及具体数值属于本项目的调校，没有使用或声称还原原厂色彩参数。

## 参数

`ColorRecipe` 前四个字段保留原有顺序；新增字段默认中性，因此旧配方能继续使用。

| 字段 | 范围 / 默认 | 行为 |
| --- | --- | --- |
| `intensity` | 0–1 / 1 | 仅控制 LUT 混合强度，其他调节独立生效 |
| `saturation` | −1–1 / 0 | 从去色到两倍色度 |
| `hue` | −1–1 / 0 | 在保持亮度的色度平面内旋转，约 ±20° |
| `contrast` | −1–1 / 0 | 以中灰为支点调整亮度对比 |
| `brightness` | −1–1 / 0 | 对 SDR 亮度做 ±0.25 的创意偏移，不是相机曝光补偿 |
| `highlights` / `shadows` | −1–1 / 0 | 平滑选择亮部或暗部，正值提亮、负值压暗 |
| `sharpness` | −1–1 / 0 | 小范围亮度细节增强；负值柔化，限制边缘过冲 |
| `clarity` | −1–1 / 0 | 更大范围的局部对比，主要作用于中间调；负值降低局部对比 |
| `grain` / `vignette` | 0–1 / 0 | 颗粒 / 暗角 |
| `hdfEnabled` / `hdfStrength` | false / 0.4 | 软件高光扩散开关及 0–1 强度，不是物理 HDF 滤镜 |
| `whiteBalanceAmber` | −9–9 / 0 | A/B 轴：正值偏琥珀，负值偏蓝 |
| `whiteBalanceGreen` | −9–9 / 0 | G/M 轴：正值偏绿，负值偏洋红 |

白平衡偏移是相机白平衡之后的软件微调，并在 LUT 之前应用。它不依赖设备手动色温能力，也不等同于 RAW 通道增益。

处理顺序：白平衡偏移 → LUT 混合 → 色相 / 饱和度 → 对比 / 亮度 / 高光 / 阴影 → 锐度 / 清晰度 → 柔光叠加 → 暗角 → 颗粒。参数范围与同名相机菜单没有数值对应关系。

## GPU 实现

取景直接采样相机 OES 纹理。普通调色融合在同一个片元着色器内，不把预览逐帧读回 CPU；锐度和清晰度各使用四个邻域采样，数值为零时跳过。

柔光开启时，从调色后的画面提取亮部，写入最长边不超过 384 px 的纹理，再做水平、垂直两遍 Gaussian 扩散，最终叠加到保留细节的中心图像。两个 RGBA 缓冲重复使用；关闭时不分配新缓冲，也不执行这些额外通道。它着重让亮部向周围扩散，不把整张照片简单模糊。

空间半径按完整画面的短边归一化，在预览旋转、裁切和照片处理中使用同一套图像坐标。照片先为完整画面生成一次柔光纹理，再按 128 行分条渲染、读回；邻域采样仍访问完整输入，避免条带接缝。预览分辨率、最终照片分辨率和手机 ISP 差异仍需在实机上评估。

`ColorRecipe.isIdentity` 检查所有会改变画面的参数。仅在整份配方中性时，照片才跳过 GPU 并返回输入 Bitmap。
