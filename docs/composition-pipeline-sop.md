# 端侧构图双支路 SOP

状态：目标架构已确定；检测模型和 `d1-omni-600M` 权重尚未锁定，当前版本不宣称双支路已在真机跑通。

## 目标

取景器保持 24–30 fps 的相机预览。分析只消费有限的最新帧，任何模型异常、过期或设备不支持都必须回退到纯相机拍摄，不能锁住快门。

```text
CameraX ImageAnalysis（一次 YUV 采样）
                 │
                 ▼
        latest-frame 分流总线
          ┌──────────────┴──────────────┐
          │                             │
  高频主体支路（目标 10–15fps）    低频构图支路（目标 1–2fps）
  YOLOv11-Nano Int8，320×320       d1-omni-600M Q4 ONNX，384×384
  BBox + confidence + label        score + problem_en + recommend_bbox
          │                             │
  置信度门限 + EMA/One-Euro        schema 校验 + 字典映射 + 插值
          └──────────────┬──────────────┘
                         ▼
              取景器：主体跟随框 + AI 推荐框 + 中文提示
```

“每帧”指预览和渲染不间断，不等于每一帧都同步执行神经网络。检测器先以 10–15fps 做真机基准，再根据 p95 延迟决定是否提高频率；显示层用平滑插值跟随预览。

## 两个分支的职责

高频支路只回答“主体在哪里”。它输出归一化坐标、置信度和有限长度的类别名，经过阈值、主目标选择和 `BoundingBoxSmoother` 后绘制主体框。YOLO 的类别集合不自动等于“任何主体”或商标主体；若要突出 Nike 等小标志，需要单独的类别定义、训练集或显著性策略，不能只依赖 COCO 预训练类别。

低频支路回答“画面如何更好”。输入为最新的 384×384 帧和英文构图指令，输出必须通过严格 schema：`score` 在 0–1、`problem_en` 为版本化字典键、`recommend_bbox` 为 0–1 归一化矩形。未知标签回退为通用中文提示，非法坐标或不完整结果直接丢弃，不更新旧框。生成式模型的一次低频任务可能包含多次 token 解码，因此 SOP 中的“一次前向”指一次有界推理会话，不承诺单个 decoder forward。

## 当前代码与目标模型

当前 `camera` 已有 `KEEP_ONLY_LATEST`、独立分析线程、帧年龄和过期结果门闸；当前 `CompositionFrameSource` 默认约 1.2 秒取一帧并缩放到最长边 384。当前应用的真实运行时是可选的 SmolVLM ONNX（256M 默认、500M 对照），权重由用户主动安装，尚未完成荣耀 Vs3 真机延迟和温升验证。

本轮新增的 `CompositionPipelineContracts` 定义了共享的归一化框、主体检测、构图建议、模型适配器和边界框平滑协议。它是双支路的接口层，不把不存在的 YOLO 或 d1 权重伪装成已安装模型。

`YOLOv11-Nano Int8` 接入前必须锁定具体导出版本、类别表、许可证、输入布局、NMS 行为和 ARM64 运行时。`d1-omni-600M` 接入前必须锁定官方来源、revision、Q4 ONNX 图、外部数据文件、视觉输入输出 shape、文本解码方式、许可证和 SHA-256；“裁剪音频分支”不能只凭名称推断已具备 Android 图像输入。

## 背压、坐标和降级

- 相机只绑定一次 `ImageAnalysis`，先完成一次 YUV → RGB/采样，再把最新帧分给两个有界消费者；不能为两个模型各建一套转换链。
- 每条支路最多一个运行任务和一个待处理最新帧。新帧到达时丢弃旧待处理帧；模型异常不影响 `ImageCapture`。
- 高频框和低频推荐框都以完整相机帧坐标表达，统一经过 `CompositionFrameGeometry` 转到取景器坐标；旋转、裁切和横竖持必须使用同一变换。
- 主体框短暂丢失时保留很短 TTL 并淡出；构图框超过年龄上限或场景切换时清除。模型切换、暂停和重绑会使旧结果失效。
- 设备负载过高时依次降低检测频率、缩短输出、暂停持续建议、释放大模型；始终保留拍摄和快门。

## 验收指标

每个模型和设备都记录：预览帧率、检测 p50/p95、构图推理 p50/p95、帧年龄、丢帧率、框 IoU/稳定性、内存峰值、温度、电量、快门响应和连续拍摄失败率。目标数字必须来自荣耀 Vs3 等实际设备，不能从模型参数量推导。

## 模型分发

模型默认外置、用户主动安装，安装界面显示来源、版本、体积、许可证和 SHA-256。模型权重仍不进入 Git；仅在开发机明确传入项目外 `edgeModelDir` 时构建带权重的 debug APK，普通 Preview/CI 构建会清除本地 staging。当前自动任务禁止自行下载大权重、新 SDK 或镜像；YOLO/d1 权重仍未锁定，不把候选模型标为“已支持”。
