# Android v0.1 · 评审计划

> **历史归档（2026-10）**：v0.1 已发布，本文是当时的评审与实施计划，保留用于溯源；当前开发版为 v0.3.0-dev，现状与构建说明见 [android-development.md](android-development.md)。

状态：范围已确认，实施中。首测设备为荣耀 Vs3；本文记录范围、开发顺序和验收标准，真机验证完成前不代表已经满足全部目标。

一期只做 Android APK；iOS 留在后续路线中。目标是把「打开 → 选视角 → 调用参数和影调 → 拍照 → 保存」做成可以日常使用的完整流程。

## 系统与首测设备

| 项目 | 建议 |
| --- | --- |
| 最低版本 | Android 12 / API 31，即 `minSdk = 31` |
| 重点验证 | Android 14 及以上；最低版本单独做兼容验证 |
| 编译与目标版本 | 开工时锁定官方最新稳定版 SDK，记录具体版本；不依赖预览版 SDK |
| 首测机 | 荣耀 Vs3，具体设备型号、底层 Android 版本和相机能力接入真机后读取 |
| 发布方式 | 先通过 GitHub Releases 提供 APK；应用商店上架另行安排 |

Android 12 是建议的兼容下限，不是对当前系统占有率的判断。系统版本不能代替相机能力检测：手动曝光、对焦和镜头信息都按实际设备判断。

荣耀 Vs3 作为首个体验基准。另补一台非折叠机，以及最低支持版本的设备；模拟器用于安装、权限和界面验证，不代替真机相机与性能验收。

## 一期拍什么、怎么拍

默认使用后置主摄，4:3、SDR JPEG。进入应用直接取景，不设首页、账户或引导轮播；首次必要的权限说明除外。

| 能力 | 一期范围与验收重点 |
| --- | --- |
| 三档视角 | 28 / 35 / 50mm 等效视角，点击切换；首版优先固定主摄裁切，避免自动换镜头造成画面跳变 |
| Snap 预设 | 保存并恢复视角、曝光设置、支持的对焦设置与影调；退出再打开也能恢复 |
| 曝光 | 自动曝光、曝光补偿；支持手动曝光的设备提供快门与 ISO 设置，按设备范围校验 |
| 对焦 | 默认自动对焦、点击对焦；支持时提供对焦锁定与手动控制。不承诺通用的米制 Snap 距离 |
| 操作 | 屏幕快门、前台音量键快门；常用参数直接可达，盲拍依靠熟悉视角与实体按键 |
| 取景 | 三分网格、水平仪、影调预览；参数面板不遮住主要取景区域 |
| 行色 | 原色与少量独立调校预设；支持标准 SDR `.cube` 3D LUT 导入、强度调节、颗粒和暗角 |
| 参数记忆 | 使用 JSON 定义配方，首版先支持本地保存、切换；配方分享放到后续版本 |
| 成片 | 影调实际写入 JPEG，保存至系统相册；保留可获取的 EXIF，正确处理方向、裁切和输出尺寸 |
| 折叠屏 | 内外屏切换、展开/折叠、旋转与后台恢复后，取景不拉伸，控件可用，设置不丢失 |

视角基于可获取的镜头与传感器信息换算，并校验预览与成片裁切。主摄若无法覆盖 28mm，不用放大画面冒充更广视角：明确提示并记录不支持情况。裁切后的实际像素尺寸如实保存。

LUT 首版建议限定为 17³ / 33³、SDR sRGB 输入输出。导入时校验尺寸、数据量与数值范围；Log、HDR LUT 和其他格式留到后续，避免同一文件在不同解释下产生错误颜色。

一期暂不包含：iOS、视频、前摄、美颜、HDR 合成、夜景多帧、RAW / DNG、峰值对焦、完整 ADJ 按键映射、相册管理与社区功能。

## 技术建议

| 部分 | 建议 |
| --- | --- |
| 语言与界面 | Kotlin、Jetpack Compose、单 Activity |
| 相机 | 优先 CameraX；需要手动控制时通过 Camera2 interop 接入，并在原型阶段验证 |
| 调色 | OpenGL ES 3.0 / GLSL，预览与照片处理复用同一套 LUT 和效果算法 |
| 状态与配置 | ViewModel、Coroutines / Flow、DataStore、kotlinx.serialization |
| 图像保存 | MediaStore、ExifInterface；保存任务在后台执行，限制并发与内存占用 |
| 工程 | Gradle Kotlin DSL、版本目录；先按 `app / camera / color` 三个模块组织 |
| 自动检查 | GitHub Actions：构建、Lint、核心算法单元测试；构建成功后提供调试 APK 制品 |

相机选型先过验证关：若 CameraX 的控制或效果接口不能满足首版要求，在产品功能展开前决定是否改用 Camera2，避免同时维护两套完整相机实现。

预览走相机 Surface 和 GPU 纹理处理，避免每帧读回 Bitmap；高分辨率拍照单独处理，后台应用相同的影调和裁切规则，再编码保存。共用算法不等于预览和照片逐像素一致，两者仍需验证曝光、白平衡和颜色解释。

一期先保证 JPEG 与 LUT 处理闭环；不引入 Rust、跨平台框架、网络服务或大型图像处理依赖。

## 开发顺序与交付

| 阶段 | 工作 | 评审时能看到什么 |
| --- | --- | --- |
| M0 · 真机验证 | 读取荣耀 Vs3 能力；验证三档裁切、手动参数、GPU 取景和调色成片；测基础启动时间 | 能力清单、关键路径验证结果、相机选型结论 |
| M1 · 拍照闭环 | 工程与 CI、权限、相机生命周期、预览、快门、JPEG 保存、音量键 | 第一个能安装、取景和保存照片的 APK |
| M2 · 街拍操作 | 三档视角、Snap 参数记忆、曝光/对焦控制、构图辅助、折叠屏布局 | 能带出门试拍的 APK，验证单手与盲拍操作 |
| M3 · 行色 | GPU 效果、内置预设、LUT 导入、本地配方、照片处理和 EXIF | 取景可看影调，保存的照片也带影调 |
| M4 · 发布候选 | 设备回归、性能优化、错误恢复、签名、构建说明与版本记录 | 可复现构建的 v0.1 候选 APK，附测试记录 |

M0 只做必要的技术验证，不扩展产品功能。每一阶段都以实际结果收敛下一步，不预先承诺日历工期。

## 验收标准

- **拍照可靠**：连续拍摄 50 张，保存张数与成功提示一致；照片能在系统相册打开，方向、视角和影调正确。处理队列满时明确反馈，不静默丢片。
- **参数真实生效**：保存的是设备实际接受的设置；不支持的控制隐藏或禁用，不能只更新界面数字。
- **状态能恢复**：权限拒绝后重试、相机被占用、切后台、熄屏及恢复时有明确状态，不持续黑屏或泄漏相机会话。
- **折叠屏可用**：反复切换内外屏与旋转，检查取景比例、点击对焦坐标和裁切；切换发生在保存过程中也不丢照片。
- **颜色有依据**：使用恒等 LUT、标准测试图和真实场景检查 LUT 解析、通道顺序、插值、裁切与方向；对照预览和成片观察明显偏色。
- **构建可复现**：固定依赖与工具版本；CI 可生成调试 APK，Release 构建通过 Lint 与必要测试。正式签名材料不入库。

性能只盯几个直接影响拍摄的指标：

| 指标 | 初步预算 / 测量方式 |
| --- | --- |
| 启动到可拍 | 荣耀 Vs3 的 Release 构建，授权完成后做 30 次冷启动；初步争取 P95 ≤ 1.5 秒。可拍要求首个有效预览、预设已应用且拍照用例已就绪 |
| 实时预览 | 正常光照、默认影调以稳定 30fps 为基线；检查持续取景、调参和保存时的卡顿及积压，暗光按实际曝光单独记录 |
| 快门响应 | 分开记录「按键到开始捕获」和「捕获到保存完成」，避免用后台保存速度代替快门速度 |
| 体积与内存 | 开启 R8 与资源裁剪，记录 Release APK 大小和连续拍摄峰值内存；不以低分辨率或丢功能换取漂亮数字 |

上述性能预算在 M0 建立基线后复核，不作为尚未实现功能的宣传结论。优化优先考虑效果合并、纹理复用、有限队列与启动关键路径。

## 本次评审需要确定

1. 一期只做 Android，最低 Android 12，首测荣耀 Vs3。
2. 主摄裁切实现三档视角，后置 4:3 JPEG 优先。
3. 首版包含 Snap、手动能力检测、实时影调和 LUT 导入；RAW 与配方分享后置。
4. 先做 M0 相机与调色验证，验证后再确定最终 CameraX / Camera2 方案。

已开始工程与功能实现，具体构建和真机验证步骤见 [Android 开发说明](android-development.md)。M0 的荣耀设备能力、实际视角与性能结论需要连接真机后补充。
