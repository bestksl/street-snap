# 取景 UI 行业调研与改造记录（T08）

日期：2026-10-18。方法：先以产品经理方式调研行业头部相机 App 的取景/操作 UI，再保守改造。原则——取景器是主角、专业控件收纳、举起即拍不打断、不炫技、逐屏在 Android 35 ARM64 AVD 上验证。

## 一、现状诊断（改造前代码走查 + AVD 截图）

证据：`CameraScreen.kt`（1309 行）与 AVD emulator-5580 截图（改造前）。竖屏为 `Column { 48dp 摆件条; Viewfinder(weight 1); ShootingControls }`，控件区是一块不透明 `surface=#101110` 面板，预览只占中间约 45% 高。

"像计算器 / 操作栏特别复杂"的具体来源：

1. **专业项常驻平铺两整排。** 快门区上方第一排 `28mm 35mm 50mm | WB | HDF`，第二排 `影调 | 原色 | 正片 | 负片 | L.单色`，全部是等宽字体（Monospace）英文缩写的 `TextButton` 胶囊，网格状排列，类似计算器按键。白平衡、柔光这类低频专业项与焦段同层常驻。
2. **取景器不是主角。** 顶部还有一条 48dp 相机摆件（CameraArtwork），加上下两排控件和 90dp 快门行，画面被压在中间；展开任一调整面板后取景器进一步缩到上半小块，整块哑光灰 `surfaceContainer=#1B1D19` 表单像"设置页"而非相机。
3. **视觉语言偏工具表单。** 全局近黑底 + 荧光黄 `#E2FF79` accent 本身克制，但控件全靠 Material `TextButton` + 圆角灰胶囊 + 大量 Monospace 标签，缺少图标、层次与"浮在画面上"的摄影语言；信息密度高、没有收纳。
4. **入口语义混乱。** 右下 `ADJ` 打开"影调"精调，但白平衡还有独立的顶部 `WB` 按钮，影调/胶片/预设三处概念分散；HDF 既是柔光开关又藏在影调参数 DIFFUSION 里。
5. **优点（改造必须保留）。** 快门大且居中、一触即发；点按对焦 / 长按锁焦 / 音量键快门；实时三分法构图框 + 中文建议是产品差异化核心；参数自动记忆；横屏侧栏、小窗滚动、无相机能力时的禁用态都有完整处理；AF/MF、P/S/M 专业能力齐全。

> 结论：不是功能太多，而是**分层和视觉语言**问题。默认拍摄态应只留"举起即拍"必需的少数控件，其余全部收进一个浮层控制面板；快门行从独立面板改为浮在取景器底部的半透明层。

## 二、行业调研结论

### 1. iOS / Android 原生相机 × 理光 GR 快拍（已完成）

**原生相机范式**：全屏取景器 + 居中大快门；模式靠底部横滑（iOS 模式条；GCam 画面任意处横滑，控件透明悬浮无黑底）；顶部仅闪光/定时等两三键，下拉才展开二级；点按对焦、对焦框旁上下滑调 EV、长按锁 AE/AF。专业能力统一"折叠"：Pro/全景进"更多"，三星"更多模式"改成不遮预览的底部弹窗，小米专业模式默认各项 Auto。代价是创造性让渡（iPhone 被批"你只管按其余我定"，HDR/锐化不可关、自动曝光连拍漂移）。

**理光 GR III 快拍哲学（事实）**：Snap 固定对焦六档 `1 / 1.5 / 2 / 2.5 / 5m / ∞`，出厂默认 **2.5m**；Full Press Snap 快门按到底跳过 AF、按预设距离释放消除对焦时滞；官方示范 2m+F8 景深约覆盖 1m–∞，P 档另有景深优先自动收 F8 泛焦；开机约 0.8s、内置挡板免摘盖；靠 Sleep 待机 + 半按快门瞬醒（完全关机仍需电源键，快门不能开机）；ADJ 杆/Fn 自定义，配置存 U1/U2/U3。逻辑是 28/40mm 广角 + 小光圈大景深 + 估焦，"举机就拍不看屏"。
**反面教材**：GR III 机背菜单被批层级深、ADJ 仅 5 槽且分配混乱、取消独立曝光补偿杆、AEL/AFL 必须按住、MF 只能滚轮。

**可直接采纳**：
1. 默认屏只留全屏预览 + 底部中央快门 + 右下缩略图 + 顶部最多两键；WB/影调/焦段/EV/HDR/ADJ 全部收进一个上滑 BottomSheet，取景器零常驻数值。
2. 快门零确认零拦截；默认不弹拍摄后预览/确认框/遮罩；音量键即快门。
3. 控件全部压到拇指热区（下 1/3 与两角），控制面板从快门上方升起。
4. EV 只在点按对焦后出现细滑条、数秒淡出，不常驻。
5. 构图辅助低干扰：极细半透明三分线；实时中文建议做非模态一行浮层、不压快门热区、可一键关，不堆参数。
6. 专业项默认隐藏但记忆；GR 的菜单教训——收纳后必须层级浅、槽位逻辑清晰。

**不适合**：拟物转盘 / 层级式相机菜单、把全手动参数搬上主屏、常驻直方图景深条。实体两段式快门、光圈环、0.8s 冷启动、腰平形态无法迁移触屏。

### 2. Halide / Obscura（已完成）

**布局**：Halide 纲领 "Stay out of the way"，取景器铺满全屏；快门居中、左下圆角缩略图、右下焦段切换；顶部"耳朵"放直方图/曝光表；可收合 Quickbar 收纳网格/RAW/定时/设置；定制 Ambrotype 蚀刻字风格但不做厚重拟物；Mark III 把 WB/闪光放进 "…" 更多菜单。Obscura v3 主动砍掉标志性拟物 Control Wheel，默认态快门上方只有三按钮（滤镜/变焦/翻转），快门左右是曝光键与对焦键，中部全留给取景。

**核心路径**：自动模式都是"启动→按快门"两步。Halide 取景区上下滑调 EV、左右滑拉焦、拖焦时对焦放大镜自动出现/抬指消失（Intelligent Activation）+ 对焦峰值；Obscura 从曝光键拖出圆转盘调节、长按复位，统一"点按展开—拖拽调节—长按复位"，调参时取景器内大字提示。

**专业控件收纳（关键）**：Halide Mark III —— 手动白平衡等低频项进 "…" 菜单，**一旦启用，图标钉在工具栏常驻高亮，提醒手动覆盖正在生效**，避免忘记 WB 毁掉整组；全手动入口被刻意移出拇指热区。Obscura —— 单一 drill-in：点 gear → 快门上方横滚选项行 → 子项在上方再出一行 → "x" 逐级返回，全 App 统一。

**缺点/批评（反面教材）**：Halide 学习曲线陡、拍一张准备 10–15s（原生约 2s）不适合抓拍、拖拽调节慢且不精确、**EV 没有便捷归零被抱怨**、边缘滑切模式有误触快门风险、仅 iOS；Obscura 订阅墙、老用户怀念转盘、层级偏多。两家后来都在做减法（Obscura 砍转盘、Halide 把手动移出热区）。

**可直接采纳**：
1. 快门周围默认只留 快门 / 焦段 / 相册（+我们的构图）四类，WB/HDF/滤镜/比例全进一个"更多"抽屉。
2. EV 取景区上下滑直调 + 临时大字数值浮层，不占常驻栏；**提供便捷归零**（长按/双击）。
3. **手动覆盖"钉一个小标记 + 高亮 + 一键复位"**（WB 非自动、MF、M/S 档、HDF 开时）——防止用户忘记手动态，这是 Halide Mark III 验证过的模式。
4. 辅助工具上下文出现：对焦峰值/放大镜只在调焦时出现，取消常驻开关式摆放。
5. 单一浅层级 drill-in 收纳，杜绝多级平铺（我们用一个 BottomSheet + 顶部分区即可）。
6. 用取景器内大字 toast / 触觉反馈替代常驻文字标签。

**不适合街拍**：ISO/快门全手动默认隐藏（Halide 自己都移出热区）；边缘滑切模式有误触风险（边缘手势只留给无破坏操作）；绕圈转盘慢、需学习；不模仿已被官方放弃的拟物相机身。

### 3. ProCamera / Lightroom（已完成）

**高密度控件如何收纳**：
- **ProCamera**：全屏取景；大量功能收进一个弹出式 Control Panel（闪光/翻转/画幅/网格/全屏）。手动控制面板是拇指区一小条，仅 M/SI/WB/MF 三个按钮；**自动（A）模式下整条坍缩为一个 WB 按钮**。交互语义：**蓝色高亮=当前可调，下划线=已锁的手动值，再点下划线钮即复位自动，长按出预设/灰卡**。另有三档界面密度 OSD（Standard/Medium/Light，极简档只剩快门）、全屏点哪拍哪（Fullscreen Trigger）、左缘右滑进相册（QuickFlick，边缘手势只做无破坏操作）。预设可保存曝光/WB/对焦组合。
- **Lightroom 相机**：底部分模式条 Auto/PRO；进 Pro 后快门上方一行图标 `Exp/Sec/ISO/WB/Focus + 重置`，**点图标才展开单根滑杆**（一次只调一项）；**双击任意图标单项复位，重置图标一键全回 Auto**。教训（反面）：安卓相机入口只在相册视图出现、被大量用户以为"砍了相机"；启动到可拍慢于原生，不适合抢瞬间；滤镜/预设放拍摄流程里多一步。

**缺点/批评**：ProCamera 被 The Sweet Setup/PhotoWorkout 批"控件藏在弹出面板、界面拥挤、小屏局促、不如 Halide 优雅"（但 PetaPixel 2026 反向认为其学习曲线最平缓；对只想要自动的人 overkill）；分离对焦点/测光点双点拖拽公认难用。Lightroom 安卓手动能力依赖厂商、入口情境化混乱、专业功能在订阅墙后。

**可直接采纳**：
1. **自动态把专业条坍缩成一个入口**：默认拍摄态只有一个"控制/ADJ"按钮，点开才是控制面板（正是我们阶段 B 的 BottomSheet）。
2. **手动态语义三件套**：高亮=可调、下划线/药丸=已锁定的手动值、再点复位；sheet 顶栏一个全局"复位"，每项可单独复位。
3. **控制面板一次只调一项**：点 WB/ISO/快门/对焦图标才展开单根滑杆，避免一面板滑杆海（对应我们影调已有"选参数→出一根滑杆"，白平衡/拍摄照此收敛）。
4. **边缘手势只做无破坏操作**（如滑出相册），绝不用于切拍摄模式/快门，避免误触（与 Halide 误触教训一致）。
5. **相机入口恒在、启动即取景**：不把相机藏进编辑器/相册；默认不弹拍摄后预览。
6. **影调/滤镜默认不占常驻空间**，进控制面板或拍后，不在快门旁铺一排。

**不适合快拍**：分离对焦/测光双点拖拽（公认难用）、M 档双拨盘常驻、对运动主体用对焦滑杆、常驻直方图/斑马纹/水平仪默认开。

### 三方共识（最终采纳依据）

1. 全屏取景器是主角；专业项默认全部收纳，自动态只剩一个控制入口。
2. 快门居中、一触即发、零确认；缩略图与控制分居快门两侧，全部落在拇指热区（下 1/3）。
3. 焦段是街拍唯一允许常驻的高频专业控件，做成快门上方一小条/药丸。
4. 任何手动覆盖（WB/MF/M·S/HDF）必须可见（钉标记/下划线）且能一键复位。
5. 控制面板用单一浅层级浮层，一次调一项，顶栏全局复位。
6. 不做拟物机身/转盘、不绕圈、不边缘滑切模式、不常驻仪表；相机入口恒在。

## 三、改造方案与采纳清单（已定稿并落地 A/B，C 缓做）

三方调研（原生/GR、Halide/Obscura、ProCamera/Lightroom）收敛出的共同原则：**全屏取景器是主角；快门居中一触即发；专业项默认收纳进单一浅层级浮层；拇指热区在下 1/3；任何手动覆盖要可见、可一键复位；不做拟物转盘/不炫技。**

分阶段（每阶段独立可构建、上 AVD 逐屏回归，不满意即回退该阶段）：

- **阶段 A — 默认拍摄态全屏化（解决"像计算器"主体）**
  - 取景器 `fillMaxSize` 铺满；移除常驻 48dp 摆件条与不透明下方控制面板外壳，控件全部改为浮在画面上的半透明层（底部加渐变 scrim 保证白字可读）。
  - 底部悬浮快门行：左缩略图、中央大快门、右"控制"入口（取代 ADJ 文案块）；均在拇指热区。
  - 快门上方一条悬浮焦段分段（28/35/50，街拍高频保留，禁用态半透明），不再是灰底表单行。
  - 顶部浮层只留：对焦模式（AF/MF/AF-L）、构图入口与实时开关；HDF/WB 不再常驻。
  - 收敛 Monospace：仅数值/焦段/AF 等"仪表读数"用等宽，中文标签用默认字体；减少灰胶囊、改用透明图标按钮 + 选中态描边/荧光黄。
- **阶段 B — 单一控制面板浮层（解决"操作栏特别复杂"）**
  - 用 `ModalBottomSheet` 承载现有 影调/胶片/白平衡/拍摄 四个分区内容（逻辑与参数组件全部复用，仅外壳从挤压取景器的内嵌面板变为浮层），打开时取景器不缩小。
  - 白平衡、HDF、EV/P/S/M、ISO/快门、网格/水平仪、相机摆件/方向、构图模型管理全部收进 sheet；移除顶栏独立 WB 按钮与两排常驻专业项。
  - **手动覆盖钉标记**：WB 非自动 / MF / M·S 档 / HDF 开时，在底部控制入口或快门行显示可点小药丸（如 "WB 多云""MF""M·ISO400""柔光"），点它直达对应分区并可一键复位——Halide Mark III 模式，防忘。
  - 当前影调（原色/正片/L.单色/胶片名）~~做一个快门行上方小药丸~~：**实现后撤销**。影调是 WYSIWYG 创意预设而非"会毁掉一张照片的手动覆盖"，常驻药丸与左下构图建议卡在画面上争抢空间（首轮截图实测交叠）；改为统一的"调整"入口，打开即落在影调分区，高频但不常驻。
- **阶段 C — 反馈与触感收尾（本轮评估后缓做，理由记录在案）**
  - EV 取景器内细滑条/上下滑：**缓做**。Halide 式上下滑与我们已有的"点按对焦、长按锁焦"手势冲突，误触代价高；当前 EV 在 sheet 拍摄区单根滑杆调节、默认态零数值、调整后以可长按复位的药丸反馈，已满足"覆盖可见+一键复位"共识，边际收益不抵回归风险。
  - 手动参数变化大字瞬时提示：缓做（锦上添花，当前药丸+右下读数已即时反映）。
  - 构图中文建议非模态浮层、不压快门热区：**已确认**（全屏预览上位于下 1/4 偏上，与 override 药丸分行，见第四节 b4/b5）。
  - 横屏侧栏路径：**已回归**（宽横屏 ≥600dp 保留原侧栏，代码未改逻辑仅共享新顶部胶囊；AVD 实测见 b13/b14）。小窗滚动、无能力机型禁用态、权限页、模型安装流程保持原代码路径，随全量单测与手工走查回归。

**明确不做**：拟物机身/机械转盘、绕圈转盘、边缘滑动切模式（误触快门风险）、常驻直方图/景深条、把全手动参数搬上主屏、新增外部依赖或图标包（用文字 + 自绘）。

## 四、逐屏验证记录

环境：Android 35 ARM64 AVD（emulator-5580，1080×2340，软件 GPU），`:app:assemblePreview` 真机安装，截图编号对应两轮迭代留档（a1–a8 阶段 A 迭代，b1–b16 阶段 B 交互回归）。

**阶段 A — 默认态全屏化（a1–a8，迭代中发现并修复的问题）**

- a1：全屏预览 + 浮层控件成立；发现影调常驻药丸与左下构图建议卡交叠 → 撤销影调药丸（理由见阶段 B 备注）。
- a2：默认态定稿——顶部仅"构图 / 实时·开 / AF"三枚半透明胶囊，底部渐变浮层上为焦段分段条 + 缩略图/快门/调整，预览铺满，"计算器"式两排 Monospace 按键与哑光灰表单消失。
- a3：影调分区在 ModalBottomSheet 内完整可用（机身摆件、影调名、选参数→单根滑杆、导入 LUT、重置）。
- a4：白平衡分区完整（模式 + A/B、G/M 漂移轴、重置漂移）。
- a5：拍摄分区完整（复位、P/A/S/M、EV 单滑杆、AF/MF 预设、网格/水平仪、相机设置入口，可下滚到构图模型管理）。
- a6：EV +1.5 后 override 药丸出现，但初始避让高度（216dp）把建议卡顶到画面中部 → a7/a8 将浮层避让收敛到 92dp（恰好越过多数机型单行药丸），建议卡与药丸分离、画面清爽。
