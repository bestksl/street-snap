## 出图方法

- **虚拟场景 imagefile 模式**：模拟器虚拟相机支持 `scene.mode = imagefile:<主机绝对路径>`（AVD 的 `environment.ini`），App 相机分析、姿态识别看到的就是该主机图片。运行中可用 gRPC `android.emulation.control.incubating.VirtualSceneService/reloadEnvironment` 在不同 imagefile 图片间热切换，无需冷启动（本批实证十余次）；mesh3d 默认房间 ↔ imagefile 的模式切换则需冷启动。
- **4:3 映射标定与 letterbox 补偿**：用自绘标定卡（文件坐标顶红/底蓝/左绿/右黄色带、角点编号）实测，imagefile 喂 **4:3（1440×1080）图时近似全幅映射**到竖幅取景区（文件 x 0→约 0.93、y 0→约 0.95）；直接喂竖版照片会被相机管线两次 cover 放大，等效只保留源图中心一小块。对策是把竖版源图等比缩放后贴入 1440×1080 黑底 4:3 画布（自写 `canvas.swift`，本批参数：图高系数 1.30、上偏 −0.095、左偏 −0.06，成像 946×1404），**仅为抵消模拟器的裁切使人物完整入镜；照片像素未做任何修改，也未与取景画面合成**。画布黑边在二次 cover 后落于取景区之外，截图中不可见。
- **mesh3d 房间与海报注入**：`pose-demo.png`、`viewfinder.png` 在默认 3D 测试房间拍摄；房间墙面海报经模拟器官方的 `poster.png` 替换机制注入测试照片（截后已恢复 SDK 原版海报）。姿态识别在海报这一平面图像上运行，属于管线功能验证，不是真人 3D 场景。
- **动态状态取证**：`screenrecord --bit-rate 12000000 --time-limit 90` 全量录屏（模拟器久置后 App 冷启动约需 25–31 秒，故先录 2 秒再启动 App、总时长 90 秒覆盖完整启动→识别→达标→轮换），再用 AVFoundation `AVAssetImageGenerator`（`appliesPreferredTrackTransform`，0.3–0.35 秒间隔）抽帧目检。达标绿帧由 PoseCoach 真实判定产生（`SCORE_READY=0.75`、连续 4 帧确认，ready 后 2200ms 自动换下一个姿势），不是手工摆造或后期改色。
- **尺寸与纪律**：原始截屏/录屏帧均为 1080×2340，用 `sips -z 1560 720` 等比缩放到 720×1560（PNG）；不拼接取景、不补造控件、不虚构状态。源照片、标注与中间产物只存本机临时目录（`/tmp/pose-fixture`、`/tmp/pose-shots`、`/tmp/lwl-emulator-ctl`），**不进入 git**。

## 证据边界

- 全部截图来自 qemu 模拟器（无头、`-gpu host`），**不代表荣耀 Vs3 真机**的成像、骨架贴合度、帧率、温升或功耗；姿态识别在平面照片/海报上运行，只验证识别与引导链路本身。
- `pose-ready.png` 的转绿是该测试照片上 PoseCoach 的真实判定（录屏全覆盖抽帧所得），可复现方式见上文；这不是真机命中率证据。
- `compose-panel.png` 中 d1-omni-600M 未安装、pose 模型 5.5 MB 已安装均为截图时设备的真实状态。
- 模拟器 HAL 不报告数字变焦，焦段条呈灰态；真机行为可能不同。

蓝色推荐框来自当前图像统计（画面分析建议），黄色框只在端侧模型对同一帧 A/B/C 候选的两轮选择都一致、且领先差距超过门限时出现。中文提示来自候选的规则理由，不伪装成模型生成。模型未选择、弃权、选择不稳定、超时或未安装时一律保留画面分析建议，界面状态行如实标注。

关于黄框采纳图的证据边界（loaded-only，勿外推）：

- 该图取自在 540×1170（213dpi）低分辨率 AVD 上**横屏**运行的 SmolVLM 256M——分析帧随方向变为 384×288、候选拼图布局改变，模型选择才真实跟随画面内容。日志记录该轮两轮选择一致（首轮/校验轮置信度 0.9947/0.9964，领先差距 0.1354/0.2191，总耗时约 10.4s，30s 预算内）。
- 采纳是**稀有事件**：同一横屏视角随后的粗扫/细扫数十个站位，以及竖屏 d1-omni-600M 与 SmolVLM 共 70+ 个站位，门闸结果几乎全为 UNSTABLE（两轮选择不一致）或弃权，未能复现第二次稳定采纳；d1 在竖屏与横屏均未观察到通过。这与「量化模型在静态/合成画面上偏位置应答、换序一致性门闸刻意从严」的离线评测结论一致。
- 1080×2340（420dpi）软件渲染下 d1 双轮常逼近或超过 30s 预算（即 edge-models.png 的超时状态），540×1170 下可在 16–22s 完成；该耗时只反映 qemu 软件渲染的模拟器，不代表真机 NPU/GPU。
