# 界面截图

图片来自安装在 Android 15（API 35）ARM64 模拟器上的 Preview APK（2026-10-18，全屏取景器新 UI）。取景为模拟器内置 virtualscene 测试房间，截图不代表荣耀 Vs3 真机或实际摄影效果。

- `viewfinder.png`（720×1560，竖屏 1080×2340 截图缩放）：全屏取景器、三分网格、画面分析（规则）蓝色推荐框与中文建议卡；状态行实时显示来源与耗时（此图为「画面分析建议 · 画面分析 2 ms · AI 比较不稳定 · 28.9 秒」，模型两轮选择不一致时如实保留蓝框）；底部渐变浮层为焦段分段条、缩略图、居中快门与「调整」入口，顶部为构图/实时/AF 胶囊。
- `camera-picker.png`（720×1560）：控制面板「拍摄」分区→「相机设置」里的相机摆件选择弹窗，五款相机与取景方向（自动/横持/竖持）；摆件只改变外观，影调单独选择。五款摆件按真机轮廓特征区分（原创矢量、非产品图）：理光 GR 扁宽平顶+左侧握把+居中定焦镜头，富士 X100VI 银色顶盖+左右双转盘+右上混合取景方窗+银环镜头，适马 fp 直角方块+无握把无窗+四角螺丝+居中卡口，松下 LX100 II 非对称台阶顶（左双转盘、右上 EVF 高台）+突出大镜头+小握把，尼康 F3 高耸五棱镜+过片扳手+握把红竖线；影调分区顶栏的同款缩略图为 76×48dp。
- `edge-models.png`（720×1560）：控制面板「拍摄」分区底部的构图辅助管理——推荐框/实时两个开关、三个可选端侧模型（SmolVLM 256M/500M、d1 决策 600M）与已安装 417.7MB 状态。此图状态行是真实的「画面分析建议 · 画面分析 2 ms · AI 比较超时 · 30.1 秒」：d1 双轮在该模拟器软件渲染下超过 30s 总预算，界面超时降级、保留画面分析建议，副文案随状态切为「模型比较超时，保留图像构图建议」。
- `model-adoption.png`（1170×540，横屏原尺寸未缩放）：端侧模型通过门闸、推荐框升级为黄色「AI 选择」的真实截图。

蓝色推荐框来自当前图像统计（画面分析建议），黄色框只在端侧模型对同一帧 A/B/C 候选的两轮选择都一致、且领先差距超过门限时出现。中文提示来自候选的规则理由，不伪装成模型生成。模型未选择、弃权、选择不稳定、超时或未安装时一律保留画面分析建议，界面状态行如实标注。

关于黄框采纳图的证据边界（loaded-only，勿外推）：

- 该图取自在 540×1170（213dpi）低分辨率 AVD 上**横屏**运行的 SmolVLM 256M——分析帧随方向变为 384×288、候选拼图布局改变，模型选择才真实跟随画面内容。日志记录该轮两轮选择一致（首轮/校验轮置信度 0.9947/0.9964，领先差距 0.1354/0.2191，总耗时约 10.4s，30s 预算内）。
- 采纳是**稀有事件**：同一横屏视角随后的粗扫/细扫数十个站位，以及竖屏 d1-omni-600M 与 SmolVLM 共 70+ 个站位，门闸结果几乎全为 UNSTABLE（两轮选择不一致）或弃权，未能复现第二次稳定采纳；d1 在竖屏与横屏均未观察到通过。这与「量化模型在静态/合成画面上偏位置应答、换序一致性门闸刻意从严」的离线评测结论一致。
- 1080×2340（420dpi）软件渲染下 d1 双轮常逼近或超过 30s 预算（即 edge-models.png 的超时状态），540×1170 下可在 16–22s 完成；该耗时只反映 qemu 软件渲染的模拟器，不代表真机 NPU/GPU。

截图用 ADB screencap 取得，竖屏三张由原始 1080×2340 等比缩至 720×1560，横屏一张保持原始 1170×540；不拼接取景、不补造黄框、不虚构控件。UI 截图为 README 展示材料，原始测试输入与照片仅保存在被 Git 忽略的本地目录。三档焦段按设备能力开放，该模拟器 HAL 不报告数字变焦故显示为不可用灰态，真机行为可能不同。

更新截图时同步检查 README 与本文件描述。默认 Preview APK 不带权重（约 21MB），模型在 App 内显式下载；不能仅看默认包体判断模型是否存在。
